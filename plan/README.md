# Plan workspace — Day Ledger (PLAN.md stage 1)

These are the **plan-chat deliverables** for a new app, kept here so the owner can
read and edit them on his phone and so they are versioned. They are pushed to the
assigned session branch at the owner's explicit request (2026-10-15).

**This directory is not the new app repository and is not the bootstrap.**
Nothing here is app code. The app repo (public, MIT, package
`io.github.pabi277.dayledger`, working name **Day Ledger**) is created only when
the owner answers the plan chat's exit gate with an approval — and it is still
pending, because the gate answer on 2026-10-15 was *revise*, after which the owner
rescoped the app to his own personal use and the spec below was rewritten around
that.

| File | What it holds |
|---|---|
| `files/docs/REQUIREMENTS.md` | **the owner's spec** — his own words, a day in his life, requirements R1–R34 with acceptance tests, the insight model, screen sketches, data model, permissions, hard limits, the personal kill test P0–P3, candidate features C1–C12 awaiting his pick, and what is out of scope |
| `files/docs/ROADMAP.md` | phases 0–6 derived from the spec, each with a "Done means" acceptance test that includes the sideloadable `app-progress-apk` |
| `files/docs/DECISIONS.md` | the anti-re-ask register — owner decisions with dates, law waivers (**none**), agent decisions (reversible), owner verification tasks |
| `files/docs/RESEARCH.md` | the Play Store research that shaped the spec (options compared, rejected with reasons, dated evidence, verdict line) and the finished dossier for the designated next app |
| `files/rule.md` | the future app repo's own self-contained operating manual |
| `files/prompt.md` | the future app repo's continuation prompt (living state) |
| `files/README.md` | the future app repo's README |
| `superseded-draft-mess-hisab-dossier.md` | the earlier mess/meal-rate research draft, superseded by the owner's revision — kept because it is the next app if this one is killed |
